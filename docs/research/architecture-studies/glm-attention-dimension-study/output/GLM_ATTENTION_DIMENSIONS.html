GLM-style attention: internal dimensions and joint scaling

Extension of the model-body study · 58 variants at~5T and~10T · GB300 and Rubin dense-spec proxy · September9,2026

Attention dimensions are no longer fixed. We vary heads, Q/KV ranks, QK/value head dimensions and indexer dimensions independently, then compare coordinated attention/body widening against body-only widening. Sparse top-K2048 and the configured four-layer index reuse remain fixed. This is an inference-cost study, not an equal-quality model comparison.

Important calibration correction discovered during the extension

The pinned AIC decode SOL formula uses the same indexer work for full-index and reused-index layers. The earlier~0.7× native GLM calibration therefore included avoidable indexer work. This extension introduces a local analytical reuse correction, keeps the old files unchanged, and re-evaluates the same98 observed GLM strata (117,172 iterations). No new hardware measurement was made.

Main architectural findings

The following examples are~5T,EP64/TP1,four requests/rank,no speculation,GB300 SOL. They compare the same MoE body unless explicitly identified as a coordinated pair.

  • KV rank is primarily a capacity knob at this load. Rank512→256 reduces modeled256K cache from14.70→9.83GiB/request/rank, raises memory-max concurrency704→1088, and changes decode only102.3→102.8TPS/user. Rank1024 raises cache to24.45GiB and reduces memory-max concurrency to384, with101.2TPS/user at the fixed four-request shape. Sparse attention reads selected KV, not the whole resident cache.
  • Head count changes latency without multiplying latent-cache size. Heads64→128 reduce decode102.3→80.7TPS/user. Cache/request stays14.70GiB, but larger weights also reduce memory headroom.
  • Body-only widening understates the cost of coordinated widening. At L64/H12288, keeping native attention internals predicts84.9TPS/user; scaling heads/Q/KV/indexer heads predicts57.9. Memory-max concurrency drops768→320 at the same body parameters. Neither pair is quality-matched.
  • Compacting attention can buy both speed and concurrency. The compact bundle gives135.5TPS/user and1344 memory-max requests versus102.3 and704 for baseline. This is an aggressive lower-dimensional hypothesis, not evidence it preserves frontier-model capability.
  • Prefill responds differently. In the EP/TP throughput screen, the~5T GB300 baseline reaches10.4K new input TPS/GPU; compact reaches15.7K and expanded4.5K. These independently optimized rates include batching differences, unlike the fixed-layout decode examples.

Checks, mechanisms and limitations

  • Every changed dimension is passed both into the model config and the analytical DSA dimension registry. The29 distinct5T configurations passed an explicit cache-memory check against L×tokens×(KV rank+2×RoPE dimension+indexer entry bytes). The10T counterparts have the same attention dimensions. This is simulator consistency, not a measured cache-allocation validation.
  • Heads and Q rank do not directly multiply stored latent KV. KV rank and indexer head dimension do. Indexer head count affects compute/projections but the key cache is shared across indexer heads.
  • The reuse correction removes index-only projection, logit and cache-read terms on reused-index layers, retaining Q/KV/output and sparse-attention work. It uses the existing absorbed-MLA SOL algebra, exact21/78 full-index fraction at depth78, and the SGLang graph for all layouts. It is a local analytical extension, not an upstream AIC fix or measured kernel.
  • The configured index_topk=2048, index_topk_freq=4 and index_skip_topk_offset=3 do not vary. Depth changes the exact full-layer fraction slightly. Model memory remains AIC's per-layer latent/indexer allocation; actual retained or shared caches could differ.
  • Shared-expert scaling correction from the body study remains. Ideal shared/routed overlap is still assumed. Expert balancing, hardware contention, exact MTP index reuse and padding are not fully modeled.
  • Some dimensions may need new or specialized kernels. SOL can evaluate the shapes without establishing backend support or efficiency. Compact attention is a lower-cost hypothesis, not evidence of equal capability. Expanded attention plausibly improves representational capacity but quality must be measured.
  • Rubin uses the inherited dense-spec hardware proxy and conservative decimal288GB capacity; GB300 uses driver-visible277.55GiB. Apparent lower Rubin memory-max concurrency is not evidence of a real capacity regression. No Rubin hardware calibration exists here.
